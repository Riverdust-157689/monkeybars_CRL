# G1 手部（Dex3-1）在悬垂测试中的控制说明

> 回答两个问题：**测试时手部关节是怎么控制的**、**实际下达的命令是什么**。
> 对应代码：`assets/g1_brachiation/build_scene.py`（映射与关键帧）、`src/m1_checks.py`（测试时序）。
> 本文所有数值都是从当前场景模型里直接读出来的（`SceneParams(grip="forward", grip_torque_scale=10)`）。

---

## 1. 手上有多少个执行器

每只手 **7 个位置伺服**（`position` actuator，Menagerie 默认 `kp=500, dampratio=1`，力矩上限由关节的 `actuatorfrcrange` 钳制）：

| 执行器 | 行程 (rad) | 原装力矩上限 | 本项目（×10） |
|---|---|---|---|
| `*_hand_thumb_0_joint` | ±1.0472 | 2.45 N·m | **24.50 N·m** |
| `*_hand_thumb_1_joint` | 左手 −0.724 … +1.047 | 1.40 | **14.00** |
| `*_hand_thumb_2_joint` | 左手 0 … +1.745 | 1.40 | **14.00** |
| `*_hand_middle_0_joint` | 左手 −1.571 … 0 | 1.40 | **14.00** |
| `*_hand_middle_1_joint` | 左手 −1.745 … 0 | 1.40 | **14.00** |
| `*_hand_index_0_joint` | 左手 −1.571 … 0 | 1.40 | **14.00** |
| `*_hand_index_1_joint` | 左手 −1.745 … 0 | 1.40 | **14.00** |

右手的行程是左手的镜像（`thumb_1` 为 −1.047…+0.724 等）。

**"×10" 是硬件层面的放宽**（真机 Dex3 做不到），它只影响"能不能抓住"，不影响控制接口本身。M1 的指力扫描结论：×1、×5 掉，×10、×20 通过单手悬垂。

## 2. 控制接口：14 个关节被压缩成 1 个标量

测试中**从不单独控制任何一根手指**。手部只有一个输入量：

$$
c\ \in[0,1]\qquad(\text{closure fraction：0=张开，1=闭合})
$$

再由一个固定映射生成 7 个关节的目标角：

$$
q^{\text{des}}_{\text{side},j}=s_{\text{side}}\cdot \texttt{FINGER\_CLOSURE}[j]\cdot c\cdot \texttt{FINGER\_CLOSED\_LEFT}[j],
\qquad s_{\text{left}}=+1,\ s_{\text{right}}=-1
$$

| 关节 $j$ | `FINGER_CLOSED_LEFT`（满卷曲角） | `FINGER_CLOSURE`（相对权重） | $c=0.50$ | $c=0.80$ | $c=0.95$ |
|---|---|---|---|---|---|
| `thumb_0` | +1.0472 | 0.85 | +0.5236 | +0.8378 | **+0.9948** |
| `thumb_1` | +1.0472 | 0.95 | +0.5236 | +0.8378 | **+0.9948** |
| `thumb_2` | +1.7453 | 0.95 | +0.8727 | +1.3963 | **+1.6581** |
| `middle_0` | −1.5708 | 0.85 | −0.7854 | −1.2566 | **−1.4923** |
| `middle_1` | −1.7453 | 0.85 | −0.8727 | −1.3963 | **−1.6581** |
| `index_0` | −1.5708 | 0.85 | −0.7854 | −1.2566 | **−1.4923** |
| `index_1` | −1.7453 | 0.85 | −0.8727 | −1.3963 | **−1.6581** |

（右手取负号。`FINGER_CLOSURE` 让"四指先包、拇指稍后"，是人为设计的圆柱抓握时序；拇指权重 0.95 而四指 0.85，使拇指略晚到位。）

**为什么是 1 维而不是 14 维**：这是 `docs/末端执行器设计.md` 的核心主张——把高维手指控制重新参数化成一个低维抓握控制器，让 CRL 只决定"何时抓、何时放"。论文里对应的一句话是：
> We intentionally restrict hand actuation to a low-dimensional grasp synergy so that the learning problem focuses on dynamic contact-switching locomotion rather than dexterous in-hand manipulation.

### 3.2 四项检查各自下达的命令时序

| 检查 | 命令 |
|---|---|
| **M1.1 双手静态悬垂**（20 s） | 全程 `ctrl` 恒定 = 上面的关键帧命令，不施加任何变化。 |
| **M1.2 单手悬垂**（8 s） | 前 0.3 s：右手 7 个执行器的 `ctrl` 从关键帧值**线性降到 0**（张开）；此后保持 0。左手保持不变。 |
| **M1.3 松手→前伸→重抓**（9 s） | ① 0–0.2 s 保持；② 0.2–0.55 s 右手张开（ramp 到 0）；③ 保持张开，让身体单臂稳定；④ t=1.05 s 用 IK 解出"把手放回杆上"的 4 个手臂关节角，并在 1.0 s 内按 $\alpha$ 从关键帧角度混合过去：`ctrl = (1−α)·ctrl_hang + α·ctrl_IK`；⑤ 当手指与杆的**真实最小距离** < 6 mm 时，把 7 个手指执行器在 0.5 s 内闭合；⑥ 之后保持。 |
| **M1.4 摆动下肢** | 在关键帧命令上叠加：`hip_pitch = base + 0.55·sin(2π·0.6·t)`，`knee = base − 0.55·sin(...)`；双手手指命令恒定不松开。 |

**一句话概括**：整个测试期间，手指只收到**一个 0→1 的开合标量**——"张开"就是把 7 个 `ctrl` 全置 0，"闭合"就是把 7 个 `ctrl` 置成上表的闭合目标；除此之外没有任何一条单独针对某根手指的指令。手臂/腰/腿则一直是位置指令，只在 M1.3 里被 IK 结果整体混合过。

## 4. 关键帧（抓握力）是怎么做出来的

不能靠"运动学摆一个已握住的姿态"——那会让杆嵌进手指 24–38 mm，初始接触冲量上千牛，把机器人弹飞。实际流程（`build_scene._settle()`）：

```text
1) gravity = 0                      # 机器人靠自身姿态支撑，不下落
   手指 ctrl: 0 → 闭合目标（0.5 s 线性上升）
2) gravity: 0 → 9.81（1.5 s 线性上升）   # 载荷平滑转移到抓握
3) 自由整定 0.6 s
4) 快照 qpos 作为关键帧 qpos
   关键帧 ctrl = 整定后的关节角（非手指） + 闭合目标（手指，保留握力）
```

即"**先合手、再加重量**"。这也是物理上真实发生的过程（人先握住杠、再把体重挂上去）。

## 5. 和 M2（CRL 动作空间）的衔接

M2 里这套接口直接变成动作向量的最后两维：

$$
a_t=[\ldots,\ g_L,\ g_R],\qquad g\in[-1,1]\ \longrightarrow\ c=\frac{g+1}{2}\ \longrightarrow\ \text{上面第 2 节的映射}
$$

预定的消融轴（`docs/执行计划.md` §3.5）：
- **A5**：1 维 → 2 维 synergy（四指 curl + 拇指 opposition 各自独立），$q^{\text{des}}=q_{\text{open}}+c\,v_{\text{curl}}+o\,v_{\text{thumb}}$；
- **A6**：连续 → 二值开合（$g\in\{0,1\}$），检验"半闭合接触技巧"是否存在；
- **A7**：换成被动 hook，隔离"主动松手"的价值。

另外两个与本说明相关的偏差需要在论文里声明：**手部力矩 ×10**，以及 **wrist_pitch/yaw 用等式锁死**（它们各 5 N·m，在悬垂时只允许 15 mm 的质心偏移，见 `docs/M0_M1_报告.md` §4.1）。
