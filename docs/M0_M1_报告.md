## 3. M0：场景与关键帧

### 3.1 机器人模型

直接用上游 Menagerie 的 **43 主动关节**版本（12 腿 + 3 腰 + 14 臂 + 14 Dex3-1 手指），不做形态简化。对原机的全部改动：

1. `grip_torque_scale = 10`：14 个手指关节的 `actfrcrange` ×10（1.4→14，2.45→24.5 N·m）。**硬件层放宽**，由你确认。
2. `lock_wrists = True`：`<equality><joint>` 锁住 `wrist_pitch` / `wrist_yaw`（各仅 5 N·m，且在悬垂载荷路径上；`solref=0.002`）。
3. 加 5 根 capsule 杆（半径 25 mm、半长 0.45 m、`condim=4`、摩擦 1.4）。
4. 求解静平衡悬挂姿态并写成 `hang` 关键帧。

### 3.2 正手 / 反手两套姿态（`GRIP_PRESETS`）

抓杆朝向不是手调出来的，而是**在手臂关节空间里搜出来的**：要求（a）手指卷曲轴 ∥ 杆轴（世界 Y），（b）手掌法向与脸的朝向（世界 +x）对齐，（c）手在肩上方。搜索出 1628 个可行姿态，再按"肘尽量落在载荷线上"筛出最终解。

| | **正手（当前，`forward`）** | 反手（旧，`backhand`） |
|---|---|---|
| `palm·(+x)`（左手/右手） | **+1.00 / +1.00** | −0.84 / −0.83 |
| 肩 pitch / roll / yaw | −2.75 / +1.50 / −1.20 | −2.60 / +0.20 / 0.00 |
| 肘 / 腕 roll | 0.50 / +0.10 | 0.15 / −1.40 |
| 杆位置（x, z） | (+0.056, +1.486) | (−0.136, +1.460) |
| 手相对肩 | 在肩**前方** | 在肩**后方** 8–13 cm |
| 质心对齐 `hip_pitch` / 残余 dx | −0.654 / **0.0000 m** | +1.300（到行程边界）/ −0.031 m |
| 臂部力矩利用率（双手悬垂） | **0.39** | 0.96 |
| 60 s 漂移 | **5.0 mm** | 13 mm |
| 单手悬垂所需指力 | ×10 | ×5 |

**正手不只是"朝向不同"，它在力学上明显更好**：手掌朝前时手落在肩前方，质心可以精确压到杆下（残余偏移 0），肘也落在载荷线上，于是臂部力矩余量从 4% 变成 61%。反手姿态则必须靠腿后摆 75° 才能勉强把质心压到杆附近，臂部长期贴着 25 N·m 上限。

### 3.3 关键帧：必须"先合手、再加重量"

| 做法 | 结果 |
|---|---|
| ❌ 运动学直接摆"手已握住" | 闭合手指与杆穿透 24–38 mm，初始冲量 ~1600 N，把机器人弹飞 |
| ❌ 手张开 → 直接在重力下合手 | 合手期间无人承重，抓握成败是抛硬币 |
| ❌ 合手后继续命令"标称姿态" | 双手同杆构成闭环，多关节同时饱和到 100% |
| ✅ **零重力合手 → 重力斜坡加载 → 松弛保持** | 全部 PASS，关节利用率出现余量 |

最终流程（`_settle()`）：`g=0` 下 0.5 s 合手 → 1.5 s 把重力斜坡到 9.81 → 0.6 s 整定 → 快照 qpos 为关键帧；**ctrl = 整定后的关节角**（"放松悬垂"），只有手指继续命令到闭合目标以保留握力。命令数值逐条列在 `docs/手部控制说明.md` §3.1。

## 4. M0：静力矩预算（`src/torque_budget.py`）

### 4.1 解析力臂

某关节的静力矩 ≈ 该链承担的重量 × 关节中心到"过杆铅垂线"的水平距离。下表是**当前正手关键帧快照**的数量级估计（把接触力当纯竖直、双臂各半），用于判断"谁先顶到上限"。

| 链 | 关节 | \|Δx\| | 双手 τ / 上限（利用率） | 单手 τ | 单手允许的最大 \|Δx\| |
|---|---|---|---|---|---|
| 臂 | wrist_pitch / wrist_yaw | 0.037–0.041 m | 6.3–6.9 / 5（**1.25–1.38**） | 12.6–13.8 | **14.8 mm** |
| 臂 | shoulder_pitch | 0.061 m | 10.3 / 25（0.41） | 20.6 | 74.1 mm |
| 臂 | shoulder_roll | 0.058 m | 9.8 / 25（0.39） | 19.6 | 74.1 mm |
| 臂 | shoulder_yaw | 0.047 m | 8.0 / 25（0.32） | 16.0 | 74.1 mm |
| 臂 | elbow | 0.036 m | 12.2 / 25（0.49） | 24.5 | 74.1 mm |
| 腰 | waist_pitch | 0.129 m（髋→膝） | 23 / 50（0.46） | — | 280 mm |

（解析口径下的理论占用率与实测 `qfrc_actuator` 会有差别：实测双手悬垂时臂部最大利用率是 **0.39**，这张表给出的是"哪个关节的力臂最大、谁最先到顶"的排序。正手姿态下所有 25 N·m 关节的力臂都只有 3.6–6.3 cm，这是与反手姿态最大的区别。）

**结论 1：正手姿态下 25 N·m 的肩/肘力臂只有 3.6–6.3 cm**（反手时肘是 16 cm），这是臂部利用率从 0.96 降到 0.39 的原因。
**结论 2：真正卡住的是腕 pitch/yaw（5 N·m，允许偏移仅 14.8 mm）**，所以锁死它们是必要的。
注意"表中 τ > 上限"不等于机器人会掉：伺服饱和的后果是该关节停在力矩上限、不再跟随目标角，整机由接触约束与其余关节找到新平衡——只要新构型仍把杆扣在手掌口袋里，悬垂就成立（60 s 测试漂移 5 mm 即为证据）。

### 4.2 Dex3 手指预算

| | 数值 |
|---|---|
| 原装指关节上限 | 1.4 N·m（拇指根 2.45） |
| 双手悬垂每指需承受 | ≈53 N → ≈**2.12 N·m** |
| 单手悬垂每指需承受 | ≈105 N → ≈**4.20 N·m** |
| 实测（正手，8 s 单臂） | ×1 掉、×5 掉（临界 0.51）、**×10 通过**、×20 通过 |
| 实测（反手，4 s 单臂） | ×1 掉、×5 通过 |

即：**原装 Dex3 连双手悬垂都在边缘，单手悬垂必然不够**；正手姿态肘部弯曲（0.50 rad）使手指要多承担一点力矩，因此需要 ×10。

## 5. 单项说明

- **M1.1**：60 s 漂移 5 mm 后稳定，无滑移、无穿模；最紧的是手指（1.00，因为我们在"用力捏"），臂部只有 0.39。
- **M1.2**：右手在 0.3 s 内张开（`ctrl` 7 条全部降到 0），左手单独承重 8 s；最紧关节为左肘（1.00）。质心摆幅 40 mm。
- **M1.3（部分）**：已验证 ① 张开后**真实脱离**（接触数归零）；② 用 IK 把右臂驱动回杆面后，手指与杆的**真实最小间距达到 −5.7 mm（即接触）**、手掌仍朝 +x、卷曲轴仍 ∥ 杆。但触发闭合后只能得到瞬时接触，无法维持——即"手到位了，但没扣住"。原因是单臂悬挂时身体下沉约 7 cm 且持续摆动，重新接近杆时的**手部相对位姿与关键帧不同**，闭合窗口只有零点几秒。这正是 CRL 要学的东西，列为 M2 第一项。
- **M1.4**：0.6 Hz 明显优于 0.8/1.0 Hz；用腰部同相激励反而减小摆幅（相位不对）。

## 7. 遗留问题与 M2 入口

1. **M1.3 重抓未完成**（最高优先级）。需要的是"到达 + 对准 + 时机"三者同时成立：接近时保持手掌朝 +x、卷曲轴 ∥ 杆，并在手-杆间距最小的窗口闭合。脚本化实现可行但需要更完整的 IK（含朝向约束）；更本质地，这就是 CRL 要学的技能链。
2. **稀疏接触图与 Dex3 抓握冲突（D6）**：进 MJX 时要么给手指加闭合限位/腱耦合，要么显式列出必要的手部自接触对。
3. **`cage_offset` 最优点较窄**：x 方向偏 1–2 cm 就抓空 → M2 的 reset 分布要精确，或显式随机化手-杆相对位姿。
4. **观测/动作接口未实现**：`执行计划.md` §3.2 的 14 维动作（含 2 维抓握）与 §1.4 的 goal 尚未落码。
5. **未做**：MJX 吞吐测试（M0.5 门限）、杆间距扫描、被动腿/主动腿消融、反手 vs 正手的学习难度对比（正手在力矩上占优，值得作为一条消融轴）。
